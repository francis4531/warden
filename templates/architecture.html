Architecture

How Warden works.

Warden is a studio for building agents and a control plane for governing them. An agent is just instructions plus a set of tools; the tools come from MCP servers you connect; and every action an agent takes passes through one governance gate before it happens. Here is the whole pipeline.

06 Audit · the record
Every thought, tool call, result, and approval decision is written to an append-only log, per run and across the whole studio, each entry stamped with its risk tier. Nothing an agent does is off the record.
The risk model
LOWReads, auto-run
Lookups, searches, file reads. No side effects, so the agent runs them on its own.
MEDReversible writes
Opening a ticket and the like. Runs automatically, but logged prominently.
HIGHIrreversible, gated
Moving money, writing files, creating PRs. Pauses for human approval before it runs.

Unrecognized tools default to HIGH. That is deliberate: a tool from a server Warden has never seen is gated until a human decides otherwise, rather than trusted by default.

A run’s life
runningthe agent is reading and calling low/medium tools
awaiting approvala high-risk tool is held; a human must approve or deny
donethe agent finished; the full trace is in the audit log
